二、先创建 P2.0 最小宿主

新增建议结构：

apps/wallpaper-host/

三、桌面拓扑探测

用 windows-rs 实现：

1. 查找 Progman。
2. 读取 Progman GWL_EXSTYLE。
3. 检查 WS_EX_NOREDIRECTIONBITMAP。
4. 发送：

SendMessageTimeout(
  Progman,
  0x052C,
  0xD,
  0x1,
  SMTO_NORMAL,
  1000
)

只在初始化或 Explorer 恢复时发送，不要每个 guardian tick 都发送。

5. 枚举顶层窗口。
6. 找到 SHELLDLL_DefView 及其宿主。
7. 枚举 WorkerW，记录：
   - HWND
   - class
   - parent
   - visible
   - rect
   - area
   - 是否包含 DefView

输出结构化诊断日志。

定义类似：

enum DesktopVariant {
    Classic,
    Raised,
    Collapsed,
}

struct DesktopTarget {
    variant: DesktopVariant,
    parent: HWND,
    insert_after: Option<HWND>,
    def_view: HWND,
    worker_w: Option<HWND>,
}

选择规则：

Raised：

- Progman 有 WS_EX_NOREDIRECTIONBITMAP。
- parent = Progman。
- insert_after = SHELLDLL_DefView。
- 壁纸窗口位于 DefView 下、系统 WorkerW 上。

Classic：

- DefView 宿主存在有效的全屏 WorkerW 兄弟。
- parent = 真正的全屏 wallpaper WorkerW。
- 不要选择 22×22 等系统内部 WorkerW。
- 使用可见性、矩形面积和虚拟屏幕覆盖率校验候选。

Collapsed：

- 没有有效的全屏独立 wallpaper WorkerW。
- DefView 位于全屏 WorkerW 宿主内。
- parent = DefView 的 WorkerW 宿主。
- insert_after = DefView。
- 这台测试机应该命中这个分支。

不要再采用“随便取第一个可见 WorkerW”的策略。

四、原生窗口必须在创建时进入正确层级

使用 tao 的 Windows 扩展，在创建 Window 时指定 parent HWND：

- with_parent_window(...)
- with_no_redirection_bitmap(false)
- 无边框
- 不可调整大小
- 不进入任务栏
- 不激活
- 初始大小覆盖目标显示器

创建后验证并记录：

- HWND
- GWL_STYLE
- GWL_EXSTYLE
- GetAncestor(GA_PARENT)
- rect
- class
- WS_CHILD
- WS_EX_NOREDIRECTIONBITMAP

要求宿主窗口：

- WS_CHILD = TRUE
- WS_EX_NOREDIRECTIONBITMAP = FALSE
- WS_EX_NOACTIVATE
- WS_EX_TOOLWINDOW
- 展示型壁纸默认不接收鼠标

Raised/Collapsed 分支按需要添加：

- WS_EX_LAYERED
- SetLayeredWindowAttributes(alpha=255)
- SetWindowPos(host, defView, ...)
- SWP_NOACTIVATE
- SWP_FRAMECHANGED（仅样式改变后调用一次）

不要先创建顶层窗口再 SetParent。

五、创建 WebView2

只有原生宿主窗口成功进入桌面层级之后，才创建 wry WebView。

使用：

WebViewBuilder::new()
  ...
  .build_as_child(&window)

保持 GPU 加速开启。

renderer 来源通过命令行传入：

cargo run --manifest-path apps/wallpaper-host/Cargo.toml -- \
  --renderer apps/desktop/out/renderer

运行前构建：

pnpm --filter @wallpaper/desktop build

不要复制 renderer 源码，也不要创建第二套 React 应用。

静态资源必须通过安全的 wry custom protocol 或等价的本地虚拟 host 加载：

- 支持 index.html
- 支持 assets/*.js 和 assets/*.css
- 正确 MIME type
- 拒绝 `..` 路径穿越
- 只允许读取传入 renderer 根目录内的文件
- 不要绑定 0.0.0.0
- 不要关闭 CSP
- 不要使用远程 CDN

页面诊断应显示：

platform: webview2
embedded: true
template: triptych_desktop_equal

六、默认关闭鼠标交互

Octos 的鼠标拦截是其交互式壁纸功能，不要复制。

正式宿主默认是展示型壁纸：

- 不安装全局鼠标 hook。
- 不把鼠标事件转发给 WebView2。
- host 使用 WS_EX_TRANSPARENT。
- host 使用 WS_EX_NOACTIVATE。
- 必要时对 WebView2 子 HWND 追加透明命中策略。
- 必要时处理 WM_NCHITTEST / HTTRANSPARENT。
- 禁止因为点击壁纸让宿主或 WebView2 获取焦点。

验收重点不是“桌面空白区域能否点击”，而是：

- 桌面图标可点击
- 图标可框选
- 右键桌面正常
- Win+D 正常
- 壁纸不抢焦点

如果 WS_EX_TRANSPARENT 与 WebView2 子窗口组合不足，必须基于 Spy++/Win32 状态定位具体拦截事件的 HWND，不能靠猜测反复叠 flag。

七、Guardian 与 Explorer 恢复

基础显示 PASS 后，在同一阶段加入最小 guardian：

- 250ms 或 500ms 检查一次。
- 健康路径必须完全 no-op。
- 不要健康时重复 SetWindowPos。
- 不要健康时重复发送 0x052C。
- 使用 IsWindow、GetAncestor、GetClassName、rect 检查。
- Explorer 重启导致 parent/host 失效时：
  1. 重新探测桌面结构。
  2. 丢弃旧 WebView。
  3. 丢弃旧 tao Window。
  4. 在 UI 线程重新创建原生窗口。
  5. 再创建 WebView2。
- 不要尝试把旧 WebView2 surface reparent 到新父窗口。
- 日志记录恢复开始、目标变体、旧/新 HWND、恢复耗时。

十、失败处理

如果基础宿主不能显示：

- 保存完整终端输出。
- 输出宿主 HWND 与父 HWND 状态。
- 输出 WebView2 初始化 HRESULT/error。
- 输出最终 URL。
- 检查静态资源请求和 MIME。
- 对比 Octos PASS 结果。
- 不要回退 Electron。
- 不要换 CEF。
- 不要开始 IPC、托盘、自动启动或编辑器集成。

如果 guardian 尚未完成但基础宿主 PASS：

- 可以将结论标记为 PARTIAL。
- 明确基础宿主已通过。
- guardian 单独留到 P2.1。
- 不要为了 guardian 失败破坏已通过的最小宿主。

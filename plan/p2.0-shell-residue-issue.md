# P2.0 壁纸"壳子"残留问题（待视觉模型分析）

> **状态**：🟡 待诊断。P2.0 核心功能 PASS（三联画在壁纸层显示、图标可交互），

> 且能看到窗口边缘。本文档整理所有已知数据，供视觉模型分析。

## 用户报告的症状

1. 三联画（蓝/绿/灰）**在壁纸层显示**，图标可点击/框选/右键 ✅
2. 但三联画**只显示左上方约 95%**——右边被裁掉了一点
3. 桌面上能看到一个**"壳子"的边缘**（窗口边框/非客户区露出）
4. 壳子上原本写着"WallpaperAI"（窗口标题），现在只能看到一点点边
5. 用户**无法区分**壳子和三联画是不是同一个窗口

## 环境

- Windows 11 22H2 (Build 22621)
- 屏幕：**2560×1600**（用户确认的真实物理分辨率）
- DPI：node koffi 查到 96（1x），但 `--device-scale-factor=1.5` 之前出现过
- Rust 进程的 `GetSystemMetrics(SM_CXSCREEN)` 返回 **2560×1600**（已用于窗口/webview 尺寸）

## 已做的修正（commit 774ff8a）

把硬编码的 `LogicalSize(1920, 1080)` 替换成 `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)`：
- 窗口创建 `with_inner_size(PhysicalSize::new(2560, 1600))`
- reparent 的 `SetWindowPos(HWND_BOTTOM, 0, 0, 2560, 1600, ...)`
- `webview.set_bounds(PhysicalSize::new(2560, 1600))`

**但用户报告壳子仍在**——说明问题不只是尺寸，可能还有：
- 窗口边框/非客户区（frameless 设置没完全生效？）
- DPI 缩放导致 webview 的实际渲染区域和窗口 client area 不匹配
- WebView2 子窗口（WRY_WEBVIEW / Chrome_WidgetWin_0）的尺寸没同步
- 多个嵌套子窗口，其中某个尺寸不对

### 矛盾点

- `GetSystemMetrics(SM_CXSCREEN)` 在 Rust 进程返回 **2560×1600**
- 但主窗口的 `GetWindowRect` 返回 **1707×1067**
- 用户真实物理分辨率是 **2560×1600**

**这说明 SetWindowPos(2560, 1600) 没有真正生效，或者被 DPI 缩放回缩了。**
窗口实际尺寸（1707×1067）= 2560/1.5 × 1600/1.5 —— 正好是 1.5x 缩放后的逻辑尺寸。

### 另一个可疑窗口

```
HWND 397604 class="Tao Thread Event Target"
  visible=true, rect=0,0 15x15
  ex=0x80800a0 (WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_LAYERED)
  parent=0x10010 (#32769 桌面)
```

这是 tao 创建的事件目标窗口，15×15 像素，可见。**可能就是用户看到的"壳子"的一部分。**

## 待视觉模型分析的问题

1. **"壳子"到底是什么**？是主窗口的边框/非客户区？还是 "Tao Thread Event Target" 那个 15×15 窗口？还是 WebView2 某个子窗口的边缘？

2. **为什么 SetWindowPos(2560,1600) 后窗口实际是 1707×1067**？最可能是 DPI 缩放——SetWindowPos 用的是物理坐标，但窗口是 DPI-aware 的，被自动缩放。需要确认 wallpaper-host 的 DPI awareness 状态，以及是否该用 logical 还是 physical 坐标。

3. **三联画只显示 95%**——是因为窗口 1707×1067 < 屏幕 2560×1600，右边/下边的壁纸区域没有窗口覆盖？还是 webview 的渲染区域和窗口 client area 不匹配？

## 下一步候选方向（供视觉模型判断后实施）

1. **DPI awareness**：wallpaper-host 可能需要显式声明 Per-Monitor V2 DPI awareness，让 SetWindowPos 的物理坐标不被缩放。tao 可能有设置，或用 windows-rs 的 `SetProcessDpiAwarenessContext`
2. **frameless 完整性**：确认 `with_decorations(false)` 真的移除了所有非客户区，可能需要手动调 SetWindowLongPtr 清 WS_CAPTION/WS_THICKFRAME
3. **"Tao Thread Event Target" 窗口**：如果它是壳子来源，需要隐藏它（SetWindowPos(SWP_HIDEWINDOW) 或 ExHide）
4. **client area vs window rect**：用 GetClientRect 确认 webview 覆盖的是 client area 而不是包含边框的 window rect

## 已落实你的 6 处调整

1. **4 态 Lifecycle**：`RecoverQueued / WaitingForPage / Running / Backoff`。`page_ready` 字段删除（生命周期 enum 已表达）。`Building` 作为 `RecoveryRequested` handler 内的同步临时阶段，未落入 enum。
2. **page-ready timeout**：默认 12s，CLI `--page-timeout-secs`（min 3）。`WaitingForPage` 超时 → drop candidate → Backoff。
3. **page-load handler 只投递 HostEvent**：闭包只捕获 `EventLoopProxy + token`，`Finished` 时 `send_event(PageLoadFinished{token, url})`。token/state/url 校验 + do_reparent 全部回到 `Event::UserEvent`。
4. **删除旧 reparent_at / 1500ms / +1s 原地重试**：page-ready 是唯一 attach gate。PageLoadFinished 后 attach 失败 → cleanup（drop webview 再 drop window）→ Backoff，不在部分 SetParent 的 HWND 上原地重试。
5. **desktop.rs 拆分**：`probe_for_recovery(&mut SpawnSession)` + `probe_topology()`。`SpawnSession` 记录上次 spawn 的 `(progman HWND, PID)`；identity 改变才发 0x052C，guardian 永不发送。
6. **do_reparent 移除 SWP_SHOWWINDOW**：候选窗口 `with_visible(false)` 创建，attach + bounds 全部成功后才 `set_visible(true)`。

其他：WindowEvent 按 WindowId 过滤；EventLoopProxy 同线程投递无 inline fallback（按你 §五）；Raised/Collapsed 仍 fail-closed（`attaches_to_desktop() && variant != Classic → Backoff`）。

## 修复的两个实机 bug（测试中发现）

1. **URL 校验过严**：wry 0.55 把 `wallpaper://localhost` 重写成 `http://wallpaper.localhost/`（virtual-host 形式）回报给 page-load handler，原 `is_entry_url` 只认 `wallpaper://` 形式导致 PageLoadFinished 被误判 mismatch。已扩展接受 6 种规范化形式。
2. **A0 guardian 误判**：A0（top-level）不 SetParent，但 guardian 仍按 desktop target.parent 校验，true_parent（桌面 #32769）≠ WorkerW 触发误恢复。`run_guardian` 增加 `attaches_to_desktop` 参数，A0 只校验 host HWND 有效性。

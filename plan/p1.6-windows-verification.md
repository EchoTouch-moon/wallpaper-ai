## 六、根因分析（更新）

### 核心判断：与初始化完成事件相关

消失精确发生在"启动完成"那一刻，这强烈暗示：

| 可能原因 | 机制 | 证据 |
|---|---|---|
| **软件渲染器初始化完成后进入空闲** | Chromium 软件渲染器在启动期间保持活跃，初始化完成后进入"空闲"状态并释放资源 | 时间精确匹配 |
| **Electron 启动保护机制失效** | Electron/Chromium 在启动期间可能有特殊的渲染保护，启动完成后恢复正常策略 | 时间精确匹配 |
| **系统桌面刷新** | Explorer 在系统启动完成后刷新桌面，重建 WorkerW 内部 Z 序 | 时间匹配 |
| **某个启动时设置的窗口样式被重置** | `show()` 后、embed 后的某些窗口样式在启动完成后被系统/Electron 重置 | 时间匹配 |

### 排除的假设

| 假设 | 状态 | 证据 |
|---|---|---|
| 后台节流（切换窗口触发） | ❌ 排除 | 用户未切换窗口，纯时间相关 |
| setBounds 触发 | ❌ 排除 | P1.5 已删除 setBounds 代码 |
| React 渲染失败 | ❌ 排除 | 启动后2分钟内三联画可见 |
| 立即消失（P1.3/P1.4） | ❌ 排除 | 有2分钟稳定期 |
| 简单后台节流 | ❌ 排除 | `backgroundThrottling: false` + 心跳均无效 |

## 九、结论

P1.6 确认了：
1. ✅ koffi WorkerW 嵌入完全正确
2. ✅ Z 序正确（启动期间图标在前，三联画在后）
3. ✅ React 渲染完全正常
4. ✅ 软件渲染模式可行
5. ❌ **启动完成后发生系统性状态变更**，导致 wallpaper 窗口被推到 WorkerW 背景后面

**这不是 P1 的失败，而是 P1 到 P2 之间必须解决的稳定性问题。** 需要实现：
- 定期 Z 序检查 + 修复（守护进程）
- 或研究 Electron/Chromium 启动完成后的行为

壳层回归根因已定位并修复。commit `a67ed4a`（已 push，`2bc34d7..a67ed4a`）。你的 BLOCKED 判断完全正确：是 set_visible 触发的 style 回写，不是 do_reparent 的清理逻辑问题，也不是多实例。

## 根因（已实证）

tao 0.35 的 `Window::set_visible(true)` 走 `WindowState::apply_diff`：检测到 `WindowFlags::VISIBLE` 位 false→true，diff 非空 → 调 `to_window_styles()` 重算 GWL_STYLE → `SetWindowLongW` 覆盖。

tao 的 `to_window_styles()`（`platform_impl/windows/window_state.rs:244`）**总是**给非 CHILD 窗口加 `WS_CAPTION | WS_SYSMENU`，只有 `WindowFlags::CHILD` 分支（line 268）才清 WS_CAPTION。我们的窗口是手动 Win32 `SetParent` 的 top-level，tao 不知道它是 child，所以走非 CHILD 分支 → WS_CAPTION 被加回，WS_CHILD 被清掉。

**实证日志**（gen=1，mode=reparent-click-through）：

```
PRE set_visible:  GWL_STYLE=0x56000000 CAPTION=false CHILD=true   ← do_reparent 清干净
POST set_visible: GWL_STYLE=0x14c80000 CAPTION=true  CHILD=false  ← tao apply_diff 全覆盖
```

WS_CAPTION false→true，WS_CHILD true→false，WS_SYSMENU false→true —— 这正是用户截图看到的 caption + Close 按钮 + resize frame。

## 为什么 P2.0 没回归

P2.0 旧流程：`set_visible(true)` 在窗口创建时调用 → 之后 MainEventsCleared 里才 `do_reparent`。do_reparent 的 style 清理在 set_visible **之后**，apply_diff 没东西可覆盖。

P2.1 我把顺序反了：`do_reparent` → `set_visible(true)`（因为候选要先 attach 再 show）。set_visible 的 apply_diff 把刚清的 style 改回去。这是 P2.1 重构引入的真实回归，不是 tao 的 bug。

## 修复

**用 Win32 `ShowWindow(hwnd, SW_SHOWNOACTIVATE)` 替代 `window.set_visible(true)`**。ShowWindow 只动 WS_VISIBLE 位，不触发 apply_diff，不重算其他 style。

具体改动（只动 `apps/wallpaper-host/src/main.rs`）：

1. `show_window_noactivate(hwnd)`：直接调 `ShowWindow(SW_SHOWNOACTIVATE)`。
2. `on_page_load_finished` 的 attach 成功分支：`rt.window.set_visible(true)` → `show_window_noactivate(hwnd)`。
3. **A0（top-level）也补 style 清理**：之前 A0 完全没清 WS_CAPTION，所以 A0 窗口本来就会带壳。新增 `prepare_toplevel_for_show(hwnd, webview)`：strip `WS_CAPTION | WS_SYSMENU | WS_THICKFRAME | WS_POPUP` → `SetWindowPos(SWP_FRAMECHANGED)` 重算 NC → 从 host client rect set_bounds。
4. **show 前 fail-closed invariant**（按你的要求）：`show_invariant_check()` 在 ShowWindow 前断言：
   - `(style & (WS_CAPTION | WS_THICKFRAME | WS_POPUP)) == 0`
   - attach 模式 `(style & WS_CHILD) != 0`（A0 跳过）
   - `(exstyle & WS_EX_APPWINDOW) == 0`
   - attach 模式 `true_parent(hwnd) == target.parent`
   - `host client w/h > 0`
   - attach 模式 `ClientToScreen(0,0)` 与 parent client origin 对齐
   
   任一不满足 → 不 show → drop WebView → drop Window → Backoff（不在部分 SetParent 的 HWND 上原地重试）。

5. **诊断模块**（按你的"立即诊断要求"）：
   - `diag::snapshot(label, ...)`：统一打印 `pid, generation, token, lifecycle, window_id, hwnd, mode` + GWL_STYLE/EXSTYLE（含 CAPTION/THICKFRAME/POPUP/CHILD/SYSMENU 位）+ has_undecorated_shadow + IsWindowVisible + true_parent(class/pid) vs expected_parent + GetWindowRect/GetClientRect/ClientToScreen(0,0)/DWM_EXT_BOUNDS。
   - 5 个时点：① candidate built（hidden）② PageLoadFinished pre-attach ③ pre-show post-attach ④ post-show ⑤ Running+1s
   - `diag::enumerate_wallpaper_windows()`：Running+1s 时 EnumWindows 列出所有 WallpaperAI / Chrome_WidgetWin_* 顶层窗口 + PID，确认单进程单 HWND。

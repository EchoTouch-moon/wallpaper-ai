## 二、已修复的问题（本次会话中发现并修复）

### 问题 1：electron-vite + koffi `require` 标识符冲突

| 项目 | 详情 |
|---|---|
| **现象** | `SyntaxError: Identifier 'require' has already been declared` |
| **根因** | electron-vite SSR 预设注入了 CommonJS shim，koffi 打包代码也声明了 `require`，同一作用域冲突 |
| **修复** | `electron.vite.config.ts` 中将 `koffi` 加入 `external` 数组 |
| **文件** | `apps/desktop/electron.vite.config.ts` |

### 问题 2：koffi 3.x 字符串类型名变更

| 项目 | 详情 |
|---|---|
| **现象** | `TypeError: Unknown or invalid type name 'wstr'` |
| **根因** | koffi 3.x 中宽字符串类型名从 `wstr` 改为 `wstring` |
| **修复** | `user32.ts` 中类型参数从 `"wstr"` 改为 `"wstring"` |
| **文件** | `apps/desktop/src/main/win32/user32.ts` |

### 问题 3：koffi 3.x 回调注册 API 变更

| 项目 | 详情 |
|---|---|
| **现象** | `TypeError: Unexpected EnumWindowsProc type, expected <callback> * type` |
| **根因** | koffi 3.x 要求 `koffi.register(fn, type)` 的第二个参数为指针类型 |
| **修复** | `koffi.register(callback, EnumWindowsProc)` 改为 `koffi.register(callback, koffi.pointer(EnumWindowsProc))` |
| **文件** | `apps/desktop/src/main/win32/user32.ts` |

## 五、问题分析

### 核心矛盾

P1.2 移除了 `transparent: true` 和 `setIgnoreMouseEvents`，依赖 Z 序结构性穿透。但用户报告的现象表明：

- 图标可见 → Z 序修正生效
- 但三联画未渲染 → 渲染内容未显示

### 可能原因

1. **窗口不透明但内容白屏** — 窗口有 opaque 背景，但 React 渲染器未正确加载或绘制
2. **global.css 背景色遮挡** — `#0b1120` 背景色填充了整个窗口，覆盖了三联画内容
3. **渲染器加载时序问题** — `embedToWallpaperLayer` 在 `loadURL` 之前执行，可能窗口内容未准备好
4. **WorkerW 内 Z 序导致渲染层被遮挡** — wallpaper 窗口虽然在图标后面，但 WorkerW 内部可能有其他窗口遮挡了渲染内容

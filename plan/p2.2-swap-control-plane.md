# P2.2 — 区域级换图最小闭环（控制平面 + 真图渲染）

- **状态**: ✅ 实机验证通过（2026-09-04）
- **分支**: `desktop/dynamic-layer-v1`
- **范围**: wallpaper-host（Rust 宿主）新增资产池 + 本地控制服务；渲染层从渐变占位升级为真图渲染 + 单 slot 实时换图。

## 1. 设计

P1.9 Electron 路线止损后，原计划中"Electron IPC + 托盘"的控制平面不存在了。本切片为 Rust 宿主建立最小的控制平面，作为后续托盘/编辑器/定时轮换的统一接入点：

```
curl / 托盘 / 编辑器（未来）
      │ POST /swap?slot=center
      ▼
control.rs（127.0.0.1 loopback，无防火墙提示）
      │ 轮换 AssetPool 游标（跨 slot 防撞图）
      │ EventLoopProxy.send_event(SwapApplied)
      ▼
main.rs 事件循环（仅 Running 态放行）
      │ webview.evaluate_script("window.__wallpaper.applySwap([...])")
      ▼
渲染层 swap-bus.ts → React setState → 仅该 slot 的 <img> 更新
```

关键决策：

| 项 | 决策 | 理由 |
|---|---|---|
| 控制通道 | loopback HTTP（`--control-port`，默认 26078，0 关闭） | 127.0.0.1 不触发 Windows 防火墙弹窗；curl 即可验证；未来托盘/编辑器复用同一 API |
| 状态真源 | 宿主 `AssetPool`（`Arc<Mutex>`） | `/manifest.json` 每次请求现序列化，**重建的 generation 加载时自动拿到当前分配**，与 P2.1 状态机天然兼容 |
| 渲染层通知 | `HostEvent::SwapApplied` + `evaluate_script` | 复用 page-load handler 的 send_event 模式；wry `!Send`，WebView 只在事件循环线程触碰 |
| 非 Running 时换图 | 池已更新、渲染层不推送 | 下一个 generation 从 manifest 恢复，最终一致 |
| 资产文件名 | `[A-Za-z0-9._-]` 白名单 | 名字直接嵌 JSON/JS 脚本，白名单免除转义/注入问题 |
| `/assets/*` 路由 | 池认识的文件优先，其余回落静态根 | Vite 产物自己的 hashed chunk 也在 `/assets/` 下（实机踩过：首次运行 index-*.js 500 → 白屏） |
| 轮换语义 | 单 slot：跳过自己当前图 + **其他 slot 占用的图**；整组：全 slot 各自轮换 | 壁纸绝不同屏显示两张相同的图；池太小（≤slot 数）才允许回退为仅跳过自己 |
| 渲染介质 | DOM `<img>` + CSS object-fit（非 Fabric） | 本切片最小闭环；Fabric + core crop 数学的迁移独立成后续切片，不改控制平面协议 |

新增/修改：

- `apps/wallpaper-host/src/assets.rs`（新）：AssetPool——目录扫描、per-slot 游标、跨 slot 防撞轮换、manifest 序列化；8 个单测。
- `apps/wallpaper-host/src/control.rs`（新）：loopback HTTP 控制服务，`GET /health`、`POST /swap[?slot=]`、`POST /reload-assets`；thread-per-conn，5s 超时。
- `apps/wallpaper-host/src/renderer.rs`：协议 handler 增加 `/manifest.json` + `/assets/*`（池名单门禁 + 静态回落）。
- `apps/wallpaper-host/src/main.rs`：`--assets` / `--control-port` 参数；`HostEvent::SwapApplied`；`on_swap_applied`（Running 门禁）。
- `apps/desktop/src/renderer/src/swap-bus.ts`（新）：`window.__wallpaper` 全局桥 + 启动期消息队列（宿主 push 早于 React mount 也不丢）。
- `apps/desktop/src/renderer/src/WallpaperStage.tsx`：加载 `/manifest.json` 渲染真图；无 manifest 环境（Electron dev/Octos/A0 无资产）保持渐变占位。
- `scripts/gen-test-assets.mjs`（新）：零依赖生成纯色 PNG 测试资产。

| 项 | 结果 |
|---|---|
| 单测（AssetPool 轮换/防撞/manifest） | ✅ 8/8 |

| `/health` 初始分配 left=img-01/center=img-02/right=img-03 | ✅ JSON 正确 |
| 渲染层加载 manifest，三块真图与 /health 一致（PrintWindow 抓图核对） | ✅ |
| 诊断徽章 platform=webview2 / embedded=true / assets=6 | ✅ |
| `POST /swap?slot=center` → 仅 center 变（img-02→img-04），左右不动（前后抓图对比） | ✅ |
| `POST /swap`（整组）→ 三 slot 各自换且互不重复 | ✅ |
| 宿主日志 `[swap] pushed N swap(s) to renderer gen=1` | ✅ |
| Explorer kill/restart → gen 1→2 恢复 Running（P2.1 回归） | ✅ |

## 3. 已知边界（后续切片）

- 渲染介质仍是 DOM img，`@wallpaper/core` 的 crop/swap 数学尚未接入（object-fit center-crop 与模板比例当前一致）。
- 托盘、全局快捷键（Ctrl+Alt+N 等）、每 slot 定时轮换（P4）尚未接——控制 API 已就绪，接入即触发。
- `/reload-assets` 后已显示的 slot 不自动刷新，需一次 swap 才会用新池。
- 多显示器（P3）未做：单屏单窗口。

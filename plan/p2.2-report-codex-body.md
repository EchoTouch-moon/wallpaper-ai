## 摘要

Electron 路线止损后，P2 计划中的"IPC + 托盘"控制平面不存在了。本切片在 Rust 宿主上重建了控制平面，并让渲染层首次渲染真实图片、支持单 slot 实时换图（无整屏重渲）。这是"点按钮，只那块图变化"验收点的落地。

## 实现

1. **控制服务（control.rs）**：loopback HTTP（默认 127.0.0.1:26078，`--control-port 0` 可关）。`GET /health`、`POST /swap[?slot=<id>]`、`POST /reload-assets`。127.0.0.1 不触发 Windows 防火墙弹窗；curl 即可驱动，未来托盘/编辑器/定时轮换复用同一 API。
2. **资产池（assets.rs）**：目录扫描 + per-slot 轮换游标。轮换时跳过本 slot 当前图**和其他 slot 正占用的图**（壁纸绝不同屏两图重复；池 ≤ slot 数时才回退为仅跳过自己）。8 个单测。
3. **协议服务扩展（renderer.rs）**：`/manifest.json` 按请求现序列化池状态——**重建的 generation 加载时自动拿到当前分配**，与 P2.1 状态机天然组合；`/assets/*` 只服务池内名单文件。实机踩坑一处：Vite 产物自身的 hashed chunk 也在 `/assets/` 前缀下，首版路由把它们 500 掉导致白屏，已改为池外文件回落静态根。
4. **渲染层**：`swap-bus.ts` 安装 `window.__wallpaper` 全局桥（带启动期队列，宿主 push 早于 React mount 也不丢消息）；`WallpaperStage` 加载 manifest 渲染 `<img>`（object-fit center-crop），applySwap 只更新被触碰 slot 的 state——React 只重渲那一个 `<img>`。无 `--assets` 时（Electron dev / Octos / A0）保持渐变占位，诊断模式不受影响。
5. **守卫**：`SwapApplied` 只在 `Running` 态 evaluate_script；非 Running 时池已更新、渲染层不推送，由下一个 generation 从 manifest 恢复（最终一致）。slot id 与资产名来自白名单（`[A-Za-z0-9._-]`），脚本拼接无转义/注入面。

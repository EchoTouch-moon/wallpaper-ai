## 三、对前一版假设的修正

### 修正 1："嵌套子窗口无有效 surface" → 未证实且被推翻

前一版（c6557c1）声称 wry 的传统 Controller 在嵌套子窗口上失败是因为"无有效渲染目标 surface"。
**A0/A1/A2 推翻了这个假设**：

- A0：传统 Controller 在顶层窗口创建成功 → 不是 wry/Controller 本身的问题
- A1：reparent 后 Controller 继续工作 → 嵌套子窗口（WorkerW 的 child）**有**有效 surface

真正的根因是 **`with_parent_window`（创建时 parent）** 让 wry 的 `create_container_hwnd` 在
一个已经是子窗口的窗口里建容器，且当时的代码还混入了 WS_EX_LAYERED +
SetLayeredWindowAttributes。这些变量没隔离，导致 E_INVALIDARG。

### 修正 2："需要 CompositionController" → 不需要

前一版建议绕过 wry 直接调 `CreateCoreWebView2CompositionController` + DirectComposition。
**A1 证明不需要**——传统 Controller + 正确顺序（顶层创建→事后 reparent）完全够用。

### 修正 3：审查"正确路线"的措辞

审查说"错误路线：创建顶层浏览器窗口→浏览器开始合成→事后 SetParent"。
**实际上这正是能工作的路线**（A1 证明）。审查的"正确路线"（创建时就指定 parent）
反而是失败的（c6557c1 的 E_INVALIDARG）。Octos 也是事后 SetParent。

教训：**理论上的"正确"不如实证**。A0/A1/A2 的隔离实验让真相浮现。

## 四、关键技术细节

### 为什么传统 Controller 能在事后 SetParent 存活（而 Electron 不能）

- **Electron BrowserWindow**：创建时带 `WS_EX_NOREDIRECTIONBITMAP`，用独立 composition surface。
  跨进程 reparent 后 surface 失去合成目标 → 不可见。这是 Electron 特有问题。
- **wry WebView2（tao 顶层窗口）**：tao 创建的 WS_POPUP 窗口有正常的 redirectable surface
  （`with_no_redirection_bitmap(false)`）。WebView2 的 swap chain 绑定到这个 surface。
  reparent 改的是窗口树（HWND parent），不影响已建立的 surface 绑定 → 可见。

### Classic 分支的正确样式组合

```text
GWL_STYLE:  WS_POPUP 清除 | WS_CHILD 加入
GWL_EXSTYLE: WS_EX_APPWINDOW 清除 | WS_EX_NOACTIVATE 加入 | WS_EX_TOOLWINDOW 加入 | WS_EX_TRANSPARENT 加入
            （Classic 分支：不加 WS_EX_LAYERED，不调 SetLayeredWindowAttributes）
```

### reparent 的正确顺序

1. 在顶层窗口创建 WebView2（surface 建立）
2. 等页面加载（1500ms 延迟，或更好的 page-load 回调）
3. 改 GWL_STYLE（WS_CHILD）
4. 改 GWL_EXSTYLE（NOACTIVATE + TOOLWINDOW + TRANSPARENT）
5. SetParent 到 WorkerW
6. SetWindowPos(HWND_BOTTOM, full-screen, SWP_FRAMECHANGED)
7. webview.set_bounds 覆盖 client area

## 七、教训

1. **隔离变量**：c6557c1 把 with_parent_window + WS_EX_LAYERED + SetLayeredWindowAttributes
   混在一起，无法定位真正原因。A0/A1/A2 的严格隔离让真相浮现。
2. **不要把相关性当因果性**：c6557c1 看到"嵌套子窗口 + 失败"就断言"嵌套导致失败"，
   但实际上失败的是创建时 parent + 样式混合，不是嵌套本身。
3. **实证 > 理论**：审查的"正确路线"（创建时 parent）理论上更干净，但实证失败；
   Octos 的"事后 SetParent"理论上像是"Electron 失败的路线"，但实证成功。
   以实测为准。
4. **判决的价值**：外部判决指出"未证实假设"+ 要求隔离实验，直接导向了 A0/A1/A2 设计，
   一次突破。这是引入外部视角的价值。
